# Phase 10 - UI Design Contract

> Visual and interaction contract for chapter review, issue-focused chat, and post-write story intelligence with durable `.leanquill/**` artifacts. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
| -------- | ----- |
| Tool | none (extension-native) |
| Preset | not applicable |
| Component library | none — VS Code `commands`, `window.showInformationMessage` / `showWarningMessage`, `QuickPick`, `TreeView` context menus, static HTML in `openQuestionsHtml.ts` / `planningPanelHtml.ts` where issues are rendered |
| Icon library | VS Code `ThemeIcon` / Codicons (`@vscode/codicons` where used in webviews) |
| Font | VS Code theme variables (`--vscode-font-family`, `--vscode-font-size`) in webviews; native controls inherit workbench font |

No React, Tailwind, shadcn, or third-party UI registry. Phase 10 continues the static TypeScript string + shared issues HTML patterns from Phases 8 and 14.

---

## Surface Contract

### Chapter review (AIR-01)

- **Primary entry:** **Chapter tree** context menu on a chapter node: run the chapter review workflow for that chapter.
- **Command parity:** a palette command with the same workflow and arguments as the tree (power users, binding-friendly).
- **Output:** **hybrid** — create a **session issue** file under `.leanquill/issues/sessions/` (aggregate), then support **promotion** of selected findings into normal typed issues under `.leanquill/issues/{type}/`. Session files are not mixed into the default triage list that skips `sessions/`.
- **Stubs (D-04):** On run start, persist **immediately** both a session stub and a chat log stub with the **same `session_id`**.
- **Persona choice (D-03):** Every run uses an author-facing **QuickPick** — no silent "always all" — choosing **one enabled persona** vs **all enabled** personas before any model or chat step.
- **Session narrative (D-05):** Session markdown follows the **session file narrative** in `Imported/data-contracts/issue-schema.md` (session header + embedded or per-finding records); formatting details are implementation-level but must be traceable to that contract.

### Issue-focused chat — "Chat about this" (ISSUE-05 / AIR-03)

- **Entry:** **Right-click** on an issue row in shared issues webviews (Planning Issues tab and bottom panel per Phase 8 parity) and any extension command that targets the same `leanquill.chatAboutIssue` flow.
- **Context bundle:** Align with D-06–D-09: **full chapter** for `chapter` and `selection` associations; for **selection**, **full chapter** plus `spanHint` as **anchor** for in-editor focus (no new partial-slice file contract in Phase 10). For **book, character, place, thread, research:** issue markdown + linked target file when applicable; **book** uses the **standard base bundle** only. **Active story memory** is **always** included (D-09).
- **Safety:** Advisory only; **no** manuscript file writes; scope matches `docs/manuscript-safety.md` and story-chat harness rules.

### Post-write story intelligence (AIR-02)

- **Triggers (D-10):** (1) **Debounced save** of a manuscript chapter `.md` → **non-blocking** native prompt with **Run** and **Dismiss** only. (2) **Explicit command** that runs the **identical** workflow (same steps after persona pick).
- **Input scope (D-11):** **Entire active chapter** manuscript file (whole-chapter pass).
- **Note updates (D-12):** Via **MetadataAction** JSON with **`requiresApproval` + `authorApproval`** for story-note writes; no direct AI patching of notes outside the applier.
- **Persona (D-13):** Same **one vs all enabled** QuickPick as chapter review, including when the user clicks **Run** on the save prompt.

### Auditability and scope limits (D-14–D-17)

- **Chat logs:** Evolve `.leanquill/chats/*.md` frontmatter toward `Imported/data-contracts/chat-log-schema.md` (summary-first; optional transcripts D-16).
- **Metadata JSONL (D-15):** Log **applied** / **rejected** / **blocked** only; **no** new **`proposed`** stream in Phase 10.
- **D-17:** **No** `master-issues.md` rollup UI, no automated consolidation surface — session outputs and explicit promotion only.

### Icons and webview density

- Reuse **Phase 8** issues list row pattern: **title**, type/association chips, status; new row action for chat uses `ThemeIcon` + label consistent with `08-UI-SPEC.md` master–detail density.
- Any summary rows added to issues HTML follow **8px** row internals and **16px** pane padding from Phase 8/17 contracts.

| ------- | -------- |

### Chat log summary (D-16)

- **Summary-first** in persisted chat log; transcript blocks are **optional** and must not block completion if capture fails.

## Interaction Contract

| Interaction | Contract |
| ----------- | -------- |
| Start chapter review from tree | Context menu on chapter node → persona QuickPick (one vs all) → create session + chat stubs → run workflow. |
| Start chapter review from command | Same workflow; if chapter unresolved, prompt to select chapter or use active editor chapter per PLAN. |
| Persona pick each run | Always show one-enabled vs all-enabled; never auto-run all without asking. |
| Create stubs before AI | Session path under `issues/sessions/` and chat path under `chats/` with same `session_id` before any LM/chat invocation. |
| Promote finding | User action (command or explicit UI) creates **normal** issue markdown via `openQuestionStore` / promotion helper; do not conflate with session file listing. |
| Chat about this issue | Row/context menu or command → `leanquill.chatAboutIssue` with D-06–D-09 paths + story memory. |
| Selection issue | After chat open, best-effort navigate/highlight `spanHint` in chapter (no new file slice contract). |
| Save → story intelligence | Debounced **InformationMessage** (or equivalent non-blocking) with **Run** / **Dismiss**; **no** AI on save without Run. |
| Run story intelligence (explicit) | Same persona QuickPick, same whole-chapter analysis, MetadataAction approval for notes. |
| No LM / chat failure | See Copywriting **Error and fallback**; may chain `workbench.action.chat.open` with partial query per existing extension pattern. |
| Blocked metadata | Show warning/error copy; log **blocked**; no apply-anyway. |

## Layout Contract

- **No** new planning workspace tab solely for "AI review queue"; primary surfaces remain chapter tree, commands, issues webviews, and native notifications.
- **QuickPick:** one-line primary label, concise description, optional detail — same as Phase 17.
- **InformationMessage:** at most **one** primary and **one** secondary action for save prompt (Run, Dismiss); do not add a third button in the contract without a new UI-SPEC revision.
- Issues **master–detail** and filter toolbar stay aligned with `08-UI-SPEC.md` (one toolbar strip, shared protocol).
- If a compact promotion hint appears in a webview, use **12px/13px** body, **2px** control radius for inline buttons, **16px** padding — match Phase 8 and 17.

## Spacing Scale

Declared values (multiples of **4** only):

| Token | Value | Usage |
| ----- | ----- | ----- |
| xs | 4px | Icon gaps, inline separators, chip padding |
| sm | 8px | List row internals, field gaps, toolbar gaps |
| md | 16px | Webview pane padding, QuickPick conceptual grouping |
| lg | 24px | Section separation in any summary or action preview |
| xl | 32px | Empty-state vertical rhythm |
| 2xl | 48px | Major webview section breaks |
| 3xl | 64px | Full-webview top/bottom only if a dedicated summary view ships |

**Exceptions:** VS Code tree row height, native notifications, and chat padding remain platform-controlled.

## Typography

| Role | Size | Weight | Line Height |
| ---- | ---- | ------ | ----------- |
| Body | 13px or `var(--vscode-font-size)` | 400 | 1.5 |
| Label | 12px | 600 | 1.3 |
| Heading | 16px | 600 | 1.25 |
| Display | 20px | 600 | 1.2 |

**Rules:** Use only **400** and **600**. Native QuickPick, tree, menus, and chat use workbench defaults. **Display** is reserved for rare empty/summary headers in webviews only.

## Color

| Role | Value | Usage |
| ---- | ----- | ----- |
| Dominant (60%) | `var(--vscode-sideBar-background)` or `var(--vscode-editor-background)` | Webview root, list background |
| Secondary (30%) | `var(--vscode-editorWidget-background)` or `var(--vscode-dropdown-background)` | Detail panel, selected rows, grouped blocks |
| Accent (10%) | `var(--vscode-button-background)` | Primary list/webview actions only: **Run** story intelligence (when implemented as a button in webview), **Open chat** / **Retry** in error panels, **Promote to issue** if shown as a single primary in a custom surface |
| Destructive | `var(--vscode-errorForeground)` | Hard validation failures, blocked unsafe paths |

**Accent reserved for:** one primary per surface — e.g. single **Promote** in a future detail action strip, or **Run** in a webview button; **not** for every menu item or row. Inline issue row **Chat about this** is a standard secondary action, not accent-colored.

**Additional tokens:** Muted: `var(--vscode-descriptionForeground)`; warning: `var(--vscode-list-warningForeground)`; border: `var(--vscode-widget-border)`. **No** hardcoded hex.

## Copywriting Contract

| Element | Copy |
| ------- | ---- |
| Primary CTA (chapter review) | Run chapter review |
| Primary CTA (story intelligence from save) | Run |
| Dismiss (save prompt) | Dismiss |
| Persona scope QuickPick title (chapter review and story intelligence) | Choose how to run this review |
| Persona scope QuickPick item — one | One enabled persona… |
| Persona scope QuickPick item — all | All enabled personas |
| Persona chooser (follow-up when "one" is selected) | Select a persona |
| Command — chapter review (palette) | LeanQuill: Run chapter review |
| Command — story intelligence (palette) | LeanQuill: Run story intelligence update for active chapter |
| Chapter tree context menu | Run chapter review |
| Issue row / context menu (ISSUE-05) | Chat about this |
| Session stub created (optional short status) | Session file and chat log started for this review. |
| Promotion command title (suggested) | LeanQuill: Promote session finding to issue |
| Promotion confirmation | Create a new triage issue from this session finding? You can edit title and type next. |
| Save prompt body | You saved a chapter. Run a **story intelligence** pass on the full chapter? Proposed **story-note** updates require your approval. **Manuscript files are never modified.** |
| No chapter selected (review command) | LeanQuill: select a chapter in the tree or open a chapter file, then run **Run chapter review** again. |
| No active chapter (story intelligence) | LeanQuill: open a saved manuscript chapter, then run **Run story intelligence update** again. |
| No enabled personas | No enabled personas in this project. Enable personas in `project.yaml` or add persona files under `.leanquill/personas/`, then try again. |
| No LM / model unavailable (title) | No chat model available |
| No LM / model unavailable (body) | LeanQuill could not use a local chat model for this run. Open **AI chat** to continue with the prepared context, or check your model provider and try again. |
| LM error / consent (generic) | This AI action could not finish. If the problem continues, run the command again or open AI chat with the same session. |
| Metadata blocked (story notes) | LeanQuill blocked this metadata action because it would write outside approved project state. |
| Stale metadata action | This metadata action is out of date. Review the latest file state before applying changes. |
| Transcript missing (D-16) | (no blocking UI; summary remains authoritative) |

**Microcopy rules:**

- Use **chapter review**, **story intelligence**, **session issue**, and **triage issue** consistently.
- Say **manuscript** or **manuscript files** in safety copy, not vague "content."
- **Sentence case** for commands, buttons, and notifications.

## Empty, Warning, and Error States

| State | Contract |
| ----- | -------- |
| No personas enabled | `showWarningMessage` with **No enabled personas** copy; do not start stubs or model calls. |
| No model / LM failure | Information or warning with **No chat model** copy; offer chat-open fallback when implemented. |
| Session/promotion with missing session file | Warn file missing; do not show orphan promotion UI. |
| Metadata not approved | Do not write; use Phase 9 / Phase 17 conflict and blocked copy patterns. |
| D-17 | Do not surface "rollup" or "master issues" automation; deferred explicitly. |

## Accessibility and Safety

- All flows reachable via **Command Palette** and **context menus**; **keyboard** operable.
- **Status** = **icon + label** where rows exist; color is reinforcement only.
- **Webview CSP** unchanged from Phase 8/14/17: `default-src 'none'`, no `unsafe-eval`, script nonce if scripts present.
- **Stubs first** (D-04) so cancel/fail still leaves audit files where implementation writes them.
- **Save** never auto-runs AI (Pitfall 2 in `10-RESEARCH.md`).
- **Manuscript** paths remain read-only for AI; **MetadataAction** and **SafeFileSystem** for allowed writes only.
