# Phase 17 - UI Design Contract

> Visual and interaction contract for AI story chat, durable story memory, and author-approved LeanQuill metadata actions. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
| -------- | ----- |
| Tool | VS Code extension native commands, context menus, QuickPick, chat draft handoff, and theme-token webviews only if a compact summary surface is needed |
| Preset | not applicable |
| Component library | none - static TypeScript-rendered markup and native VS Code surfaces, matching `openQuestionsHtml.ts`, `planningPanelHtml.ts`, and `chapterContextPane.ts` patterns |
| Icon library | VS Code `ThemeIcon` / Codicons |
| Font | VS Code theme variables (`--vscode-font-family`, `--vscode-font-size`) in webviews; native controls inherit workbench font |

No React, Tailwind, shadcn, Radix, or third-party UI registry is in scope for this VS Code extension phase.

---

## Surface Contract

### Story Chat Entry Points

- General entry: command title **LeanQuill: Start Story Chat** opens an unsent chat draft for the LeanQuill story chat harness.
- Contextual entries: issue, character, place, thread, theme, research item, chapter, and editor selection commands use labels in the form **Chat about this {target}**.
- Entry points use existing VS Code context menus and command palette placement; do not add a new Planning workspace review queue in v1.
- Chat draft must include a compact context summary: launch source, target label/path/id, included paths, excluded paths, manuscript scope, and reminder that LeanQuill advises but never authors manuscript prose.
- General story chat includes no manuscript prose by default. Chapter or selection chat may include only the relevant chapter or selected range. Multi-chapter context requires explicit author approval before the draft is built.

### Chat Draft Surface

- Primary surface is the user's active chat provider opened with `workbench.action.chat.open` and `isPartialQuery: true`.
- Cursor/Copilot-style draft prefix: `@leanquill-story-chat `.
- Claude fallback hint: `/agent:leanquill-story-chat <story question>`.
- The draft should be unsent so the author can inspect, edit, or cancel before any model interaction.
- Fallback notification, when chat cannot be opened: "Open your AI chat and invoke LeanQuill-Story-Chat with your story question. For Claude, use: /agent:leanquill-story-chat <your story question>."

### Story Memory Browser

- Surface type: native QuickPick first; selecting an entry opens the memory markdown/YAML record in the editor.
- Row label: memory topic.
- Row description: association label plus status, for example `Chapter: ch03.md - Current`.
- Row detail: source chat id and updated timestamp.
- Empty state is notification/QuickPick copy, not a new dashboard.
- Superseded memory remains visible when the author chooses an "All memory" command or filter; default list shows active/current memory first.

### Metadata Action Review

- Proposed metadata actions are reviewed inline in the AI chat first, per D-14.
- Portable extension baseline: command **LeanQuill: Apply Metadata Action** validates and applies an accepted action record through extension code.
- Native tool confirmation may be added for Copilot/VS Code, but the contract must still work with Cursor and Claude text-confirmation flows.
- Review summary must show operation, target path, field path, old value when known, new value, rationale, source chat/session id, and risk.
- Low-risk chat logs and automatic session memory summaries may be saved automatically. Entity/story-note metadata actions require explicit author approval before application.
- Hard-blocked proposals show an error and are logged as blocked/rejected; they are never applied.

### Action Log

- Action log is durable project state, not a visual queue.
- Open/read flows may use a native command or open the compact log file directly.
- Each visible action row or summary uses status + text, never color alone: proposed, applied, rejected, blocked.

## Status Presentation

### Memory Status

| Status | Display Label | Icon Suggestion | Contract |
| ------ | ------------- | --------------- | -------- |
| active | Current | `lightbulb` | Default visible story memory. |
| superseded | Superseded | `history` | Older record remains auditable and linked from newer memory. |
| archived | Archived | `archive` | Hidden from default list unless an all-memory flow is selected. |

### Metadata Action Status

| Status | Display Label | Icon Suggestion | Contract |
| ------ | ------------- | --------------- | -------- |
| proposed | Needs review | `question` | Show target, field, old/new values, and rationale before approval. |
| applied | Applied | `pass` | Show timestamp and approval method. |
| rejected | Rejected | `circle-slash` | Preserve rationale or transcript excerpt when available. |
| blocked | Blocked by safety rules | `warning` | Explain the block reason and next step. |

Status identity must be icon + label first. Color may reinforce but never carry meaning alone.

## Interaction Contract

| Interaction | Contract |
| ----------- | -------- |
| Start general story chat | Command opens an unsent story chat draft with project metadata and lightweight LeanQuill indexes only; `manuscriptScope = none`. |
| Chat about issue | Context menu on issue rows/files opens story chat with issue record, association context, and bounded relevant chapter excerpt only when the issue/span implies it. |
| Chat about entity | Context menu on character/place/thread/theme rows opens story chat with entity metadata, linked chapters list, and no chapter prose unless the author approves it. |
| Chat about research | Context menu on research item opens story chat with research metadata/path and summary context; it does not copy unrelated research files into the prompt. |
| Chat about chapter | Chapter tree or outline command opens story chat with the selected chapter as the maximum manuscript scope. |
| Chat about selection | Editor selection command opens story chat with the selected range plus chapter identity; if selection is empty, offer chapter chat instead. |
| Include multiple chapters | Show QuickPick with selected chapter set and confirmation copy before adding any extra chapter prose to the context bundle. |
| Save automatic memory | After chat summary generation, low-risk session memory is saved under `.leanquill/memory/` and surfaced with a short success notification: `Saved to story memory.` |
| Supersede memory | Confirmation copy: `Supersede this memory entry? LeanQuill keeps the older record for audit.` Older files are not deleted. |
| Apply metadata action | Author approves inline in chat or invokes `LeanQuill: Apply Metadata Action`; extension validates schema, path, old value, and domain rules before writing. |
| Block unsafe action | Show error copy and log status `blocked`; do not offer "apply anyway" for manuscript writes, path traversal, unconfigured roots, schema-invalid payloads, or destructive deletes. |
| Conflict on old value | Show conflict copy, keep the proposed action unapplied, and ask the author to regenerate or revise the action. |

## Layout Contract

- Do not introduce a new Planning workspace review queue for Phase 17.
- Native QuickPick rows should stay compact: one-line topic/title, concise description, optional detail.
- Any webview summary introduced by implementation must reuse existing LeanQuill table/card density: 16px pane padding, 8px control gaps, 24px section separation, 2px control radius for table controls, and VS Code theme tokens.
- Proposed metadata action summaries must be scannable in this order: status, operation, target, field, old value, new value, rationale, source chat.
- Chat draft context summary uses short labeled lines rather than dense prose.
- Long paths truncate in the middle or wrap with `word-break: break-word`; never overflow horizontally.
- Primary action placement: one primary action per surface. In chat/action review contexts, reserve primary emphasis for applying an approved metadata action or starting story chat.

| Token | Value | Usage |
| ----- | ----- | ----- |

| ---- | ---- | ------ | ----------- |
| Body | 13px or `var(--vscode-font-size)` | 400 | 1.5 |
| Label | 12px | 600 | 1.3 |
| Heading | 16px | 600 | 1.25 |
| Display | 20px | 600 | 1.2 |

Rules:

- Use only weights 400 and 600.
- Native chat, QuickPick, tree, and menu typography stays native to VS Code.
- Label style is reserved for metadata keys, action fields, source/risk captions, and section captions.
- Display style is reserved for a top-level webview summary heading only; do not use it inside dense action rows.

## Color

| Role | Value | Usage |
| ---- | ----- | ----- |
| Dominant (60%) | `var(--vscode-sideBar-background)` or `var(--vscode-editor-background)` | Webview root, inactive surfaces, memory empty state background |
| Secondary (30%) | `var(--vscode-editorWidget-background)` or `var(--vscode-dropdown-background)` | Action preview cards, selected rows, grouped metadata blocks, dropdowns |
| Accent (10%) | `var(--vscode-button-background)` | `Start Story Chat`, `Apply approved action`, and inline retry/open links only |
| Destructive | `var(--vscode-errorForeground)` | Blocked unsafe actions, rejected destructive proposals, validation errors |

Accent reserved for: `Start Story Chat`, `Apply approved action`, `Open story memory` from an empty state, and inline retry/open links inside error panels. Do not use accent for every context menu item, status label, chip, or row hover.

Additional semantic tokens:

- Warning/stale: `var(--vscode-list-warningForeground)` for stale `oldValue`, stale associations, or unresolved target paths.
- Muted: `var(--vscode-descriptionForeground)` for context summaries, association chips, and memory details.
- Border: `var(--vscode-widget-border)` for action preview cards and table/list separators.

No hardcoded hex colors.

## Copywriting Contract

| Element | Copy |
| ------- | ---- |
| Primary CTA | Start Story Chat |
| Empty state heading | No story memory yet |
| Empty state body | Start a story chat to preserve session summaries and decisions as LeanQuill memory. |
| Error state | LeanQuill could not build story chat context. Check the target still exists, then start the chat again. |
| Destructive confirmation | Supersede memory entry: Supersede this memory entry? LeanQuill keeps the older record for audit. |

Additional fixed copy:

| Element | Copy |
| ------- | ---- |
| General command title | LeanQuill: Start Story Chat |
| Issue context menu | Chat about this issue |
| Chapter context menu | Chat about this chapter |
| Selection context menu | Chat about selection |
| Entity context menu | Chat about this {entity} |
| Research context menu | Chat about this research |
| Apply command title | LeanQuill: Apply Metadata Action |
| Automatic memory success | Saved to story memory. |
| Action applied success | Applied LeanQuill metadata action. |
| Action rejected | Metadata action was not applied. |
| Unsafe action blocked | LeanQuill blocked this metadata action because it would write outside approved project state. |
| Old value conflict | This metadata action is out of date. Review the latest file state before applying changes. |
| Multi-chapter confirmation | Include these chapters in story chat context? Full manuscript context is never added automatically. |

Microcopy rules:

- Use **story chat**, **story memory**, and **metadata action** consistently.
- Use **manuscript prose** for safety warnings; do not shorten this to "content" where ambiguity could imply AI writing.
- Use sentence case for command descriptions, buttons, QuickPick placeholders, notifications, and helper text.
- State what LeanQuill did or blocked; avoid anthropomorphic AI copy.

## Empty, Warning, and Error States

| State | Contract |
| ----- | -------- |
| No memory records | QuickPick or summary surface shows the empty heading/body from the copy table and offers Start Story Chat if a button/link exists. |
| No chat provider available | Show fallback hint with the LeanQuill-Story-Chat invocation; do not fail silently. |
| Target missing | Warn that the target no longer exists and offer general story chat without that target. |
| Selection missing | If command is invoked with no selection, offer chapter chat for the active chapter or cancel. |
| Stale old value | Show warning state and block apply until the author regenerates or revises the action. |
| Schema-invalid action | Show validation error, log blocked status, and do not write. |
| Unsafe path | Show blocked copy above and do not offer override. |

## Accessibility and Safety

- All core flows must be keyboard-operable through command palette, context menus, QuickPick, chat input, and editor focus.
- Status must not rely on color alone; pair every state with text and, where available, an icon.
- Webview CSP must align with existing Planning/Issues webviews: `default-src 'none'`, nonce scripts only when message passing is required, and no `unsafe-eval`.
- Chat drafts are unsent by default so authors can inspect context before model interaction.
- General story chat must not include manuscript prose by default.
- Chapter/selection context must be visibly bounded in the draft summary.
- Full-manuscript context is never automatic.
- AI output must remain advisory; the UI must not label model output as accepted project truth until the author approves or LeanQuill saves low-risk memory.
- Metadata writes must be applied by extension code through `SafeFileSystem` and schema/domain validators, never by direct agent file edits.
- Hard-block attempts to write manuscript chapter prose, target unconfigured paths, perform path traversal, use unknown operations, produce schema-invalid payloads, or execute destructive deletes.
